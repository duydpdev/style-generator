# Migrating from 5.x to 6.0

6.0.0 has two breaking changes: the root entry point `@duydpdev/style-generator` now exports only the generator, and the `plugin` key of `style-gen.config.json` is gone. The generated CSS and the `--sg-*` variables are unchanged: regenerating `theme.css` after the upgrade produces the same file.

For earlier upgrades see [`4.x-to-5.0.md`](./4.x-to-5.0.md) and [`3.x-to-4.0.md`](./3.x-to-4.0.md). The full rules live in [`README.md`](../../README.md).

## Before you upgrade

**1. Find every import of the 13 moved symbols from the root.** Run this from your repository root; a hit is an import that must move to a subpath (the table below says which):

```bash
rg -n -U --pcre2 -g '*.{ts,tsx,mts,cts,js,jsx,mjs,cjs,vue,svelte,astro}' \
  'import[^;]*\b(createDesignTokens|createVariantMapper|toKebabCase|resolveSpacing|resolveSpacingProps|Breakpoint|defaultScreens|COLOR_STATES|DEFAULT_BORDER_VALUES|DEFAULT_ROUNDED_VALUES|DEFAULT_SPACING_PROPERTIES|borderProperties|roundedProperties)\b[^;]*from\s*[\x22\x27]@duydpdev/style-generator[\x22\x27]' .
```

A removed import fails the build (TypeScript error `has no exported member`, or `does not provide an export named` at runtime), so nothing breaks silently.

**2. Check `style-gen.config.json` and `package.json["style-gen"]` for a `plugin` key.** It was optional since 5.2.0 and `init` has not written it since. If you still have one, delete it together with the old `plugins/theme-plugin.ts` (see [`plugin` config key removed](#plugin-config-key-removed)).

**3. Pin the version exactly** (`6.0.0`), change the imports and the pin in one commit, and build before merging.

## Breaking changes

### Root barrel is generator-only

`@duydpdev/style-generator` now exports `generate`, `generateThemeCss`, `defineTheme`, `defineOptions`, `formatZodError` and the types. Everything else was already available on a subpath; import it from there:

| Symbol                                                                                                                                                                            | 5.x                         | 6.0                                 |
| --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------- | ----------------------------------- |
| `createDesignTokens`, `Breakpoint` (value and type), `defaultScreens`, `COLOR_STATES`, `DEFAULT_BORDER_VALUES`, `DEFAULT_ROUNDED_VALUES`, `borderProperties`, `roundedProperties` | `@duydpdev/style-generator` | `@duydpdev/style-generator/tokens`  |
| `createVariantMapper`, `toKebabCase` (`COLOR_STATES` too)                                                                                                                         | `@duydpdev/style-generator` | `@duydpdev/style-generator/cva`     |
| `resolveSpacing`, `resolveSpacingProps`, `DEFAULT_SPACING_PROPERTIES`                                                                                                             | `@duydpdev/style-generator` | `@duydpdev/style-generator/spacing` |

```ts
// 5.x
import {
  defineTheme,
  generate,
  Breakpoint,
  createVariantMapper,
} from "@duydpdev/style-generator";

// 6.0
import { defineTheme, generate } from "@duydpdev/style-generator";
import { Breakpoint } from "@duydpdev/style-generator/tokens";
import { createVariantMapper } from "@duydpdev/style-generator/cva";
```

Every type except `Breakpoint` is still exported from `.` and from `@duydpdev/style-generator/types`. `Breakpoint` is both a value and a type, so it comes from `/tokens` in either role.

Why: the root pulled the typed-token, CVA and spacing helpers into every consumer that only wanted `generate()`. With the narrower root, a build script that imports `generate` no longer carries them, and the root bundle shrinks.

### `plugin` config key removed

`style-gen.config.json` and `package.json["style-gen"]` accept `$schema`, `theme`, `output` and the generator options. A `plugin` key now fails like any other unknown key, and `style-gen doctor` no longer prints a `Script` line. `doctor` exits 1 with:

```text
  Config  (style-gen.config.json         ) ❌ Invalid
plugin → Unrecognized key: "plugin"
```

Fix: delete the `plugin` key and the old `plugins/theme-plugin.ts` it pointed at, or run `style-gen init`, which drops the key while merging the rest of your config. The Vite and Next plugins (`styleGenVite`, `styleGenNext`) and `style-gen generate` already emit the CSS, so no replacement is needed.

## Rollback

Pin `5.4.x` (`yarn add @duydpdev/style-generator@5.4.1`). Both changes are import and config edits only, so reverting them restores the 5.x behavior; generated CSS needs no change.
