# Upgrading from 7.x to 8.0

8.0.0 moves every generator option into `style-gen.config.json`, makes the plugins and `style-gen generate` write a typed `theme.tokens.ts`, renames `backDropBlurs` to `backdropBlurs`, and removes migration code for versions that never reached npm.
The generated CSS, the `--sg-*` variables and the `@source inline` output are unchanged: regenerating `theme.css` after the upgrade produces the same file.

For earlier upgrades see [`6.x-to-7.0.md`](./6.x-to-7.0.md), [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) and [`3.x-to-4.0.md`](./3.x-to-4.0.md). The full rules live in [`README.md`](../../README.md).

## Before you upgrade

Run this from your repository root. Every hit is handled by one of the sections below; a hit in an unrelated variable can be ignored:

```bash
grep -rnE "backDropBlurs|themePath|outDir|resolveSpacingProps|COLOR_STATES|splitLayout\(" --include=*.ts --include=*.tsx --include=*.vue --include=*.json .
```

Pin the version exactly, change the config, the plugin call and the imports in one commit, and run `style-gen doctor` and `style-gen generate --check` before merging.

## B1. Plugins take only `root`

`styleGenVite` and `styleGenNext` no longer accept `themePath`, `outDir` or `options`. Every generator option lives in `style-gen.config.json` (or `package.json["style-gen"]`).
Move `themePath` to `theme`, `outDir` to the directory of `output`, and `options` to the same keys in the config file. `root` is the directory that holds `style-gen.config.json`; every path in the config resolves from it.
Passing any other key throws an error that points at this section.

Before:

```ts
// vite.config.ts
import { options } from "./src/options";

export default defineConfig({
  plugins: [
    styleGenVite({
      themePath: "src/theme/theme.json",
      outDir: "src/theme",
      options,
    }),
  ],
});
```

After:

```json
{
  "theme": "src/theme/theme.json",
  "output": "src/theme/theme.css",
  "coverage": { "colors": { "opacities": [10, 20, 50, 80] } }
}
```

```ts
// vite.config.ts
export default defineConfig({
  plugins: [styleGenVite()],
});
```

Next.js: `styleGenNext({ themePath, outDir, options })(nextConfig)` becomes `styleGenNext()(nextConfig)`.
Nuxt runs the config from another directory, so give it the root: `styleGenVite({ root: fileURLToPath(new URL(".", import.meta.url)) })`.

## B2. `theme.tokens.ts` is generated on every emit

The plugins and `style-gen generate` write `theme.tokens.ts` next to `theme.css` (config key `tokensOutput`; default: the directory of `output`).
App code imports `tokens` from it instead of calling `createDesignTokens(theme, options)`, so `options.ts` is deleted. `createDesignTokens` stays for a second theme created at runtime.
Commit the tokens file, keep `theme.css` git-ignored, and add `style-gen generate --check` to CI: it writes nothing and exits 1 when the tokens file is missing or differs from the theme and config.
The file exports `tokens`, `Tokens`, `themeAxes` and `ThemeAxesState`.

Before:

```ts
// src/theme.ts
import { createDesignTokens } from "@duydpdev/style-generator/tokens";

import { options } from "./options";
import themeJson from "./theme/theme.json";

export const tokens = createDesignTokens(themeJson, options).DesignTokens.Web;
```

After:

```ts
// src/theme.ts
import themeJson from "./theme/theme.json";

export { tokens, type Tokens } from "./theme/theme.tokens";
export const theme = themeJson;
```

```bash
style-gen generate --check
```

## B3. `style-gen tokens` default path

`style-gen tokens` now writes beside `output` (it wrote beside the theme file). `--out` is unchanged.

Before:

```bash
style-gen tokens
# wrote src/theme/theme.tokens.ts, next to theme.json
```

After:

```bash
style-gen tokens
# writes next to the file named by "output" in style-gen.config.json
```

## B4. `themeAxisAttributes` is not generic

`themeAxisAttributes<typeof theme>(state)` becomes `themeAxisAttributes(state)`. Type the state with `ThemeAxesState` from the generated file.

Before:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { theme } from "./theme";

const attributes = themeAxisAttributes<typeof theme>({ theme: "dark" });
```

After:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { ThemeAxesState } from "./theme/theme.tokens";

const state: ThemeAxesState = { theme: "dark" };
const attributes = themeAxisAttributes(state);
```

## B5. `backDropBlurs` is now `backdropBlurs`

The theme key, `themeAxes.<axis>.<variant>.backdropBlurs`, `DesignTokens.Web.backdropBlurs`, `coverage.backdropBlurs`, `RecipeTokens.backdropBlurs` and the `createCn` input are renamed. The classes and the `--sg-backdrop-blur-*` variables do not change.
Find every hit with `grep -rl backDropBlurs .`.

Before:

```json
{ "colors": { "primary": "#0af" }, "backDropBlurs": { "md": "12px" } }
```

After:

```json
{ "colors": { "primary": "#0af" }, "backdropBlurs": { "md": "12px" } }
```

## B6. One export site per symbol

Each symbol is exported from one subpath only. `COLOR_STATES` comes from `@duydpdev/style-generator/cva` (removed from `./tokens`). `DefaultBreakpointKeys`, `ResponsiveValueStrict` and `SpacingKey` come from `@duydpdev/style-generator/types` (removed from `.` and `./spacing`).

Before:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/tokens";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/spacing";
```

After:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/cva";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/types";
```

## B7. `resolveSpacingProps` is removed

Use `splitSpacingProps` (`./recipes`) or `splitSpacing` (`./ui`) for component props, or call `resolveSpacing` once per property.

Before:

```ts
import { resolveSpacingProps } from "@duydpdev/style-generator/spacing";

const { className, style } = resolveSpacingProps(
  props,
  tokens.spacingProperties,
);
```

After:

```ts
import { splitSpacing } from "@duydpdev/style-generator/ui";

const { className, style, rest } = splitSpacing(
  props,
  tokens.spacingProperties,
);
```

## B8. `splitLayout` takes an options object

The positional arguments after `props` become one object.

Before:

```ts
const split = splitLayout(
  props,
  box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
);
```

After:

```ts
const split = splitLayout(props, {
  recipe: box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
});
```

## B9. `RecipeFn` is typed by its tables

`recipeFromTables(tables)` returns a function whose parameter type is derived from the tables, so a misspelled variant is a compile error. Remove the `RecipeFn` annotation, or pass the tables type, where you wrote it by hand.

Before:

```ts
export const buttonRecipe: RecipeFn = recipeFromTables(buttonTables);
```

After:

```ts
export const buttonRecipe = recipeFromTables(buttonTables);
```

## B10. Migration helpers are removed

`style-gen doctor` no longer scans for pre-5.0 `--sg-<color>` variables. `style-gen init` no longer drops removed config keys (`plugin`, `extraSources`, `axes`) from an existing config. A `themes` key in a theme file now produces the generic unrecognised-key error.
If you are on 4.x or earlier, upgrade to 7.x first and follow those guides.

Before:

```json
{
  "theme": "src/theme/theme.json",
  "extraSources": ["hover:bg-{primary,secondary}"]
}
```

After:

```json
{ "theme": "src/theme/theme.json" }
```

## New in 8.0 (nothing to change)

`style-gen generate --check`; the `tokensOutput` config key; `style-gen schema` also writes `style-gen.config.schema.json` (`--config-out`), which editors use for the `$schema` key of the config file; `style-gen init --yes` answers every prompt with its default and never overwrites an existing file.

```bash
style-gen schema --config-out style-gen.config.schema.json
style-gen init --yes
```

## Rollback

Pin 7.x (`yarn add @duydpdev/style-generator@7.2.1`), then revert the config, the plugin call and the imports.

```bash
yarn add @duydpdev/style-generator@7.2.1
```
