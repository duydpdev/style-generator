# Upgrading from 8.x to 9.0

9.0.0 finishes the colour-naming change that 8.3 deprecated: `contrastText` reads only `<intent>Foreground`, `COLOR_STATES` becomes a table that also maps a `Selected` sibling to `aria-selected:`, and the repository-only canvas wrapper script is removed.
The generated CSS and the `--sg-*` variables are unchanged for a theme that already uses the v2 names; a theme with a `<intent>Selected` colour gains one `@source inline("aria-selected:…")` line.

For earlier upgrades see [`7.x-to-8.0.md`](./7.x-to-8.0.md), [`6.x-to-7.0.md`](./6.x-to-7.0.md), [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) and [`3.x-to-4.0.md`](./3.x-to-4.0.md). The full rules live in [`README.md`](../../README.md).

## Before you upgrade

Upgrade to the latest 8.x first and run `style-gen doctor`: it warns on every `on<Intent>` key whose `<intent>` is a colour and names the key to rename to. The 8.x doctor skips a state key such as `onPrimaryHover` when the theme has no `primaryHover` colour; the grep below finds it, and the 9.0.1 doctor warns on it. Then run this from your repository root; every hit is handled by one of the sections below:

```bash
grep -rnE "\bon[A-Z][a-zA-Z0-9]*\b|states: *\[|COLOR_STATES|check-design-canvas" --include='*.json' --include='*.ts' --include='*.tsx' --include='*.mts' --include='*.cts' --include='*.vue' --include='*.js' --include='*.mjs' --include='*.yml' --exclude-dir=node_modules .
```

A hit such as `onClick` or `onboarding` is not a colour key and can be ignored.

## B1. `contrastText` reads only `<intent>Foreground`

`contrastText(colors, intent, fallback)` returned `text-on-<intent>` when the theme declared `on<Intent>` and no `<intent>Foreground`. It now returns `text-<intent>-foreground` or `text-<fallback>`; an `on<Intent>` key is not read, so a button that relied on it renders the fallback text colour.
Rename each key in `theme.json`, including `themeAxes` overrides, and every class that names it:

| 8.x key          | 9.0 key                  | Class                                                                 |
| ---------------- | ------------------------ | --------------------------------------------------------------------- |
| `onPrimary`      | `primaryForeground`      | `text-on-primary` → `text-primary-foreground`                         |
| `onDanger`       | `dangerForeground`       | `text-on-danger` → `text-danger-foreground`                           |
| `onPrimaryHover` | `primaryForegroundHover` | `hover:text-on-primary-hover` → `hover:text-primary-foreground-hover` |
| `on<Intent>`     | `<intent>Foreground`     | `text-on-<intent>` → `text-<intent>-foreground`                       |

A state moves after `Foreground`, because `createVariantMapper` finds a state sibling as `<token>` + state. When the theme already has the 9.0 key, merge the two colours by hand instead of renaming: `style-gen doctor` prints `<target> exists: merge <key> into it and remove <key>` for that case.

Before:

```json
{ "colors": { "primary": "#2563EB", "onPrimary": "$white" } }
```

After:

```json
{ "colors": { "primary": "#2563EB", "primaryForeground": "$white" } }
```

Regenerate `theme.css` and `theme.tokens.ts` (`style-gen generate`, or start the dev server), then run `style-gen doctor`: it prints no `on<Intent>` line when every key is renamed.

## B2. `COLOR_STATES` is a table; `states` takes `ColorState[]`

`COLOR_STATES` was `["hover", "active"]`. It is now a table of `{ suffix, variant }` rows, exported from `./cva` with the `ColorState` type:

```ts
[
  { suffix: "Hover", variant: "hover" },
  { suffix: "Active", variant: "active" },
  { suffix: "Selected", variant: "aria-selected" },
];
```

`suffix` is appended to a colour key to find its sibling (`primary` + `Selected` → `primarySelected`) and `variant` is the Tailwind variant the sibling's class is chained behind (`aria-selected:bg-primary-selected`, which applies when the element has `aria-selected="true"`). The registry emits the matching `@source inline` line, so the class is built.

Code that passes `{ states: COLOR_STATES }` needs no change. Any other use of `COLOR_STATES` now reads rows, not strings: a template literal such as `` `${state}:…` `` compiles but builds `[object Object]:…`, `(typeof COLOR_STATES)[number]` is a row (`{ suffix: "Hover"; variant: "hover" } | …`, assignable to `ColorState`), not `"hover" | "active"`, and `(typeof COLOR_STATES)[number]["variant"]` is `"hover" | "active" | "aria-selected"`, so a `switch` over the old union meets a third value; use `state.variant` for the Tailwind variant and `state.suffix` for the key suffix. A hand-typed list of state names is a type error; write the rows instead:

Before:

```ts
createVariantMapper("bg", tokens.colors, { states: ["hover"] });
```

After:

```ts
import {
  createVariantMapper,
  type ColorState,
} from "@duydpdev/style-generator/cva";

const states = [
  { suffix: "Hover", variant: "hover" },
] as const satisfies readonly ColorState[];
createVariantMapper("bg", tokens.colors, { states });
```

A state name that 8.x kebab-cased for you (`"focusVisible"`) becomes a row with its Tailwind variant written out: `{ suffix: "FocusVisible", variant: "focus-visible" }`. The grep above finds an inline list only; check a `states` list held in a variable too. Keep the list a literal (`as const`) so the mapper returns literal class types. A state that is not in `COLOR_STATES` gets no `@source inline` line, so declare its classes with your own `@source inline(...)` next to the generated import.

A colour key that already ended in `Selected` (`rowSelected` next to `row`) now gains the `aria-selected:` class on the base key. Rename it when that is not what you want.

## B3. `scripts/check-design-canvas.mjs` is removed

The repository-only wrapper that forwarded to the canvas checker is gone. Run the CLI command instead; the default manifest ships at `node_modules/@duydpdev/style-generator/dist/canvas/design-canvas-standard.json`.

Before:

```bash
node scripts/check-design-canvas.mjs --canvas design/canvas --theme styles/theme.json
```

After:

```bash
style-gen canvas check --canvas design/canvas --theme styles/theme.json
```

See [`style-gen canvas check`](../reference/cli.md) for the flags.

## Rollback

Pin the last 8.x, then revert the theme renames and the `states` changes.

```bash
yarn add @duydpdev/style-generator@8.3.0
```
