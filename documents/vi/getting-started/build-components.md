# Xây dựng component từ theme

Một component đi từ theme, qua token, qua recipe, qua `cn`, đến markup. Đoạn mã dưới đây phản chiếu `examples/design-system`, workspace package mà app harness dùng để dựng các component mẫu ([`examples/design-system/README.md`](../../../examples/design-system/README.md)); mỗi bước chỉ import các subpath an toàn cho trình duyệt (`./tokens`, `./cva`, `./recipes`, `./types`, `./ui`), nên không có mã Zod hay Node nào lọt vào client bundle.

```text
src/theme.json            → the theme (source of truth)
style-gen.config.json     → every generator option (plugin, CLI)
src/theme.tokens.ts       → generated by the plugin / `style-gen generate` (commit it)
src/tokens.ts             → re-exports `tokens`, exports the theme's type
src/recipes/*.ts          → headless recipes (cva + createVariantMapper)
src/cn.ts                 → clsx + tailwind-merge aware of the theme's classes
src/axes.ts               → themeAxisAttributes(state), typed by ThemeAxesState
```

## 1. Theme

Một file JSON ([Cấu hình theme](../reference/theme.md)) chứa các design token; một file config chứa mọi tùy chọn của bộ sinh. Các plugin Vite và Next cùng CLI đọc chính file đó, nên các dòng `@source inline` và các token có kiểu không thể lệch nhau:

<!-- embed: examples/design-system/style-gen.config.json -->

```json
{
  "$schema": "./style-gen.config.schema.json",
  "theme": "src/theme.json",
  "output": "src/styles/theme.css",
  "tokensOutput": "src/theme.tokens.ts",
  "breakpoints": ["md", "lg"],
  "coverage": { "colors": { "opacities": [10, 20, 50, 80] } }
}
```

Mảng `breakpoints` viết dạng literal thu hẹp `(typeof tokens)["breakpoints"][number]` thành `"md" | "lg"` trong file tokens được sinh ra. Tất cả các key: [Tùy chọn](../reference/options.md).

## 2. Token

Plugin và `style-gen generate` ghi các key token an toàn cho trình duyệt cạnh file CSS dưới dạng `theme.tokens.ts`. Hãy commit file đó và import `tokens` từ nó; `style-gen generate --check` thất bại trong CI khi file bị thiếu hoặc lỗi thời. Hãy để file này cho Prettier: nó có một dòng `// prettier-ignore` trước mỗi export và không có gì khác, nên hãy loại nó khỏi mọi công cụ khác có thể ghi lại file (Biome, dprint, oxfmt, `--fix` stylistic của ESLint, một glob của lint-staged), nếu không `--check` sẽ báo nó lỗi thời ([Khắc phục sự cố](../troubleshooting.md#file-tokens-bị-thiếu-hoặc-lỗi-thời)). Import theme JSON như một module (`resolveJsonModule`) để giữ kiểu literal của từng key, và export cả hai từ một nơi:

<!-- embed: examples/design-system/src/tokens.ts -->

```ts
import type { ColorVariant } from "@duydpdev/style-generator/types";

import themeJson from "./theme.json";
import { tokens } from "./theme.tokens";

/** The theme's literal type — feeds `ColorVariant<Theme>`, `ThemeAxesState<Theme>`, … */
export type Theme = typeof themeJson;

export const theme = themeJson;

/** Browser-safe typed token arrays, generated from `theme.json` + `style-gen.config.json` into `./theme.tokens.ts` (commit it). */
export { tokens };

/** A color token key, or `key/step` with a step from `coverage.colors.opacities`. */
export type ColorValue =
  | ColorVariant<Theme>
  | `${ColorVariant<Theme>}/${(typeof tokens)["opacities"][number]}`;
```

`createDesignTokens(theme, options)` từ `./tokens` chỉ dành cho theme thứ hai được tạo lúc runtime. Các mảng trong `tokens` được liệt kê ở [Design token](../reference/tokens.md).

## 3. Recipe: `createVariantMapper` và `COLOR_STATES`

`createVariantMapper(prefix, keys)` biến các key token thành tên class. Với các key ngang hàng `primaryHover` và `primaryActive` trong theme, `{ states: COLOR_STATES }` gộp chúng vào class của key gốc:

```ts
import {
  COLOR_STATES,
  createVariantMapper,
} from "@duydpdev/style-generator/cva";

import { tokens } from "./tokens";

const bg = createVariantMapper("bg", tokens.colors, { states: COLOR_STATES });
// bg.primary      → "bg-primary hover:bg-primary-hover active:bg-primary-active"
// bg.primaryHover → "bg-primary-hover"
// bg.danger       → "bg-danger"
```

Hãy truyền `COLOR_STATES` thay vì tự gõ bảng trạng thái: đó cũng là bảng mà các dòng `@source inline` dùng (`Hover` → `hover:`, `Active` → `active:`, `Selected` → `aria-selected:`). Hãy truyền các key camelCase như trong `tokens.colors` (`primaryHover`, không phải `primary-hover`). `prefix` được định kiểu là các tiền tố mà registry bao phủ, nên `createVariantMapper("fill", …)` là lỗi kiểu: không có dòng `@source inline` nào giữ class đó. [`createVariantMapper`](../reference/cva.md) mô tả `allowUnregisteredPrefix` cho trường hợp hiếm hoi bạn tự khai báo các class.

Một headless recipe ghép các mapper bằng `recipeFromTables` (bên dưới là class-variance-authority); các component của framework bọc nó lại. Hãy liệt kê các intent mà component cung cấp bằng `satisfies` trên các key màu: đổi tên hoặc xóa một màu trong `theme.json` thì trình biên dịch đánh dấu đúng dòng đó thay vì sinh ra một class không còn tồn tại.

<!-- embed: examples/design-system/src/recipes/button.ts#intents -->

```ts
/**
 * The semantic intents the components expose. `satisfies` is the DX anchor:
 * rename or remove one of these colors in `theme.json` and the compiler fails
 * here, on the exact line, instead of silently shipping a class that no
 * longer exists (an `Extract<…>` would silently drop it).
 */
export const intents = [
  "primary",
  "secondary",
  "success",
  "danger",
] as const satisfies readonly ColorVariant<Theme>[];

export type Intent = (typeof intents)[number];
```

`recipeFromTables(tables)` trả về một `RecipeFn<typeof tables>`, được định kiểu theo tên các variant trong bảng của nó: đừng chú thích kết quả bằng `RecipeFn` trần, vì cách đó bỏ qua phép kiểm tra này ([UI kit](../reference/ui.md#recipefromtables-recipetables-varianttable-recipeprops-recipefn-recipevariantprops)). Các class có modifier opacity (`bg-primary/10`) không được bao phủ theo mặc định: hãy viết chúng nguyên văn trong một file nguồn mà Tailwind quét, hoặc liệt kê các mức trong `coverage.colors.opacities` ([`coverage`](../reference/options.md#coverage-cắt-tỉa-các-dòng-source-inline-theo-từng-nhóm-token)).

## 4. `cn`: gộp class có tính đến các class của theme

`tailwind-merge` mặc định không biết `text-16-medium`, `shadow-md` hay `rounded-pill` của theme, nên có thể giữ lại sai class. `createCn` bọc `clsx` và một `tailwind-merge` được mở rộng bằng các token của theme; `class-variance-authority`, `clsx` và `tailwind-merge` vẫn là dependency của ứng dụng:

<!-- embed: examples/design-system/src/cn.ts -->

```ts
import { createCn } from "@duydpdev/style-generator/ui";

import { tokens } from "./tokens";

/** The design-system theme's `cn` (`createCn` from `@duydpdev/style-generator/ui`). */
export const cn = createCn(tokens);
```

`cn("rounded-md", "rounded-pill")` giữ lại class đứng sau, và các class typography và shadow của theme cũng vậy. Component gọi `cn(buttonRecipe({ … }), className)`.

## 5. Các trục theme trên DOM

`themeAxisAttributes(state)` trả về các attribute `data-<axis-kebab>` của các trục đang hoạt động; `"base"` hoặc một trục bị bỏ qua thì không phát ra gì. Hãy định kiểu `state` bằng `ThemeAxesState` từ file `theme.tokens.ts` được sinh ra, file này liệt kê các trục và variant của `theme.json`. Nó dùng cùng công thức đặt tên attribute với các selector CSS, nên DOM và CSS không lệch nhau:

<!-- embed: examples/design-system/src/axes.ts -->

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { ThemeAxesState } from "./theme.tokens";

/**
 * The DOM attributes that switch the theme's axes on, typed by `theme.json`:
 * `axisAttributes({ theme: "highContrast", palette: "forest" })` →
 * `{ "data-theme": "high-contrast", "data-palette": "forest" }`. `"base"` (or
 * an omitted axis) emits nothing. Spread on `<html>`, or pass to Nuxt's
 * `useHead({ htmlAttrs })`.
 */
export const axisAttributes = (
  state: ThemeAxesState,
): Readonly<Record<string, string>> => themeAxisAttributes(state);
```

Hãy spread kết quả lên `<html>` (React: `<html {...axisAttributes(state)}>`; Nuxt: `useHead({ htmlAttrs: axisAttributes(state) })`). Một nút chuyển hoàn chỉnh nằm trong [công thức](../cookbook.md#nút-chuyển-chế-độ-tối).

## 6. Spacing prop: `splitSpacingProps`

Một component nhận các prop spacing (`p`, `px`, `gap`, …, một số hoặc `{ base, md, lg }`) tách chúng khỏi phần còn lại bằng `splitSpacingProps` từ `./recipes`. `SpacingProps<(typeof tokens)["breakpoints"][number]>` lấy các key breakpoint từ tokens được sinh ra, nên `{ xl: 4 }` là lỗi kiểu khi `xl` không có trong `breakpoints`:

```ts
import {
  splitSpacingProps,
  type SpacingProps,
} from "@duydpdev/style-generator/recipes";

import { tokens } from "./tokens";

type Props = SpacingProps<(typeof tokens)["breakpoints"][number]> & {
  id: string;
};
declare const props: Props;

const { spacing, rest } = splitSpacingProps(props, tokens.spacingProperties);
// with props = { p: 4, mx: { base: 2, md: 4 }, id: "x" }:
// spacing.className → "sp-p sp-mx"
// spacing.style     → { "--sg-sp-p": "1rem", "--sg-sp-mx": "0.5rem", "--sg-sp-mx-md": "1rem" }
// rest              → the remaining props (className, children, …)
```

Class và các biến style được đặt trên cùng một phần tử. [Spacing](../reference/spacing.md) trình bày một component `Box` và các quy tắc.

## 7. Layout prop: `splitLayout`

Một component layout (`Box`, `Flex`, `Stack`, `Grid`) nhận spacing, các variant của recipe và kích thước inline làm prop. `splitLayout` phân loại chúng trong một lượt: recipe biến các prop variant thành class, `spacingKeys` thành các class `.sp-*` và biến, `sizeKeys` thành inline style (một số là px), và mọi thứ còn lại nằm trong `rest`:

```ts
import { createVariantMapper } from "@duydpdev/style-generator/cva";
import {
  createCn,
  mergeStyle,
  recipeFromTables,
  splitLayout,
} from "@duydpdev/style-generator/ui";

import { tokens } from "./tokens";

const cn = createCn(tokens);
const box = recipeFromTables({
  base: "flex",
  variants: { rounded: createVariantMapper("rounded", tokens.borderRadius) },
});

declare const props: {
  rounded: "pill";
  p: number;
  width: number;
  className: string;
  id: string;
};

const split = splitLayout(props, {
  recipe: box,
  spacingKeys: tokens.spacingProperties,
  variantKeys: ["rounded"],
  sizeKeys: ["width"],
});
export const element = {
  ...split.rest,
  className: cn(split.className, props.className),
  style: mergeStyle(split.style),
};
```

`extra` (tùy chọn) chứa các variant riêng của component, chúng thắng các prop. `Box` của harness trong [`examples/harness/src/ui/Box.tsx`](../../../examples/harness/src/ui/Box.tsx) là bản đầy đủ; các tùy chọn nằm ở [UI kit](../reference/ui.md#splitspacing-splitlayout-splitlayoutoptions-split).
