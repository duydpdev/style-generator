# AC6 proof — `theme.schema.json` rejects unknown keys

DEV.3 Task 3 requires proof that a `theme.json` referencing
`"$schema": "./theme.schema.json"` gets editor-side autocomplete and a
warning on a typo'd key (e.g. `colours` instead of `colors`). The coding
agent that ran this proof has no way to drive a real VSCode window and
observe the JSON Schema language-service squiggle, so this document
substitutes a non-visual, reproducible proof: run the JSON Schema
generated by `z.toJSONSchema(ThemeSchema)` through an actual JSON Schema
validator and confirm the same rule VSCode's language service would use
(`additionalProperties: false`) rejects the unknown key.

**The VSCode visual check itself is UNVERIFIED** — nobody has opened the
file in an editor and watched a squiggly line appear. What is verified below
is that the schema file VSCode would load is structurally capable of
producing that warning, because a spec-compliant validator rejects the same
input VSCode's language service would flag.

## Why ajv, and why it isn't a new dependency

The instructions were to use a JSON Schema validator "available in
`node_modules`" and not add a new dependency just for this proof. `ajv`
(`8.18.0`) is already present in `node_modules` as a **transitive**
dependency of the existing devDependency toolchain (confirmed via
`require.resolve("ajv/package.json")` — it does not appear in
`package.json`). Because it's transitive rather than declared, it is used
here only in a throwaway script for a one-time proof, never inside the
committed test suite (a committed test depending on an undeclared
transitive package would silently break the moment that upstream package
drops or bumps `ajv`).

`z.toJSONSchema()`'s default output targets JSON Schema draft 2020-12
(`$schema: "https://json-schema.org/draft/2020-12/schema"`), so the proof
uses ajv's `ajv/dist/2020` build (`Ajv2020`), which supports that draft;
ajv's default export only supports draft-07.

## Commands run

```bash
# 1. Generate the schema the same way `style-gen schema` does.
node_modules/.bin/tsx -e "
  import { z } from 'zod';
  import { ThemeSchema } from './src/core/themeSchema.ts';
  import { writeFileSync } from 'node:fs';
  writeFileSync('/tmp/schema-proof/theme.schema.json',
    JSON.stringify(z.toJSONSchema(ThemeSchema), null, 2));
"

# 2. Validate a good theme and a theme with an unknown 'colours' key against
#    the generated schema using ajv/dist/2020 (Ajv2020, draft 2020-12).
node scripts/_autocomplete-proof.mjs   # throwaway, deleted after this proof
```

`scripts/_autocomplete-proof.mjs` (deleted — reproduce inline if needed):

```js
import { readFileSync, writeFileSync } from "node:fs";
import Ajv2020 from "ajv/dist/2020.js";

const schema = JSON.parse(readFileSync("theme.schema.json", "utf8"));

const goodTheme = { colors: { primary: "#3B82F6" } };
const badTheme = { colors: { primary: "#3B82F6" }, colours: {} };

const ajv = new Ajv2020({ strict: false, allErrors: true });
const validate = ajv.compile(schema);

console.log("valid (good theme):", validate(goodTheme));
console.log("valid (bad theme, 'colours' typo):", validate(badTheme));
console.log("errors:", JSON.stringify(validate.errors, null, 2));
```

## Output

```
--- generated theme.schema.json (excerpt) ---
{
  "$schema": "https://json-schema.org/draft/2020-12/schema",
  "type": "object",
  "additionalProperties": false,
  "required": [
    "colors"
  ]
}

--- validating a theme.json WITHOUT the typo ---
valid: true

--- validating a theme.json WITH an unknown key (colours) ---
valid: false
errors: [
  {
    "instancePath": "",
    "schemaPath": "#/additionalProperties",
    "keyword": "additionalProperties",
    "params": {
      "additionalProperty": "colours"
    },
    "message": "must NOT have additional properties"
  }
]

additionalProperties error present: true
```

## Conclusion

- The theme with only known keys (`colors`) validates successfully.
- The theme with the `colours` typo is rejected specifically because of
  `additionalProperties: false` at the schema root — the exact mechanism
  VSCode's built-in JSON Schema language service (`vscode.json-language-features`)
  uses to underline unknown properties and offer autocomplete for the known
  ones, since both consume the same JSON Schema draft 2020-12 document
  produced by `style-gen schema`.
- **Not verified**: actually opening `examples/react-v4/src/theme/theme.json`
  (or any of the other example theme files, all of which now carry
  `"$schema": "./theme.schema.json"` and a co-located generated
  `theme.schema.json`) in VSCode and watching the warning/autocomplete
  appear on screen. That step requires a human or a GUI-driving agent and
  was out of reach in this environment.
