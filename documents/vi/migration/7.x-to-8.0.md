# Nâng cấp từ 7.x lên 8.0

8.0.0 chuyển mọi tùy chọn của generator vào `style-gen.config.json`, để các plugin và `style-gen generate` cùng ghi một file `theme.tokens.ts` có kiểu, đổi tên `backDropBlurs` thành `backdropBlurs`, và gỡ mã migration của những phiên bản chưa từng lên npm.
CSS sinh ra, các biến `--sg-*` và kết quả `@source inline` không đổi: sinh lại `theme.css` sau khi nâng cấp cho ra đúng file cũ.

Với các lần nâng cấp trước, xem [`6.x-to-7.0.md`](./6.x-to-7.0.md), [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) và [`3.x-to-4.0.md`](./3.x-to-4.0.md). Các quy tắc đầy đủ nằm trong [`README.md`](../../README.md).

## Trước khi nâng cấp

Chạy lệnh này từ thư mục gốc repo. Mỗi kết quả tìm thấy được xử lý bởi một mục bên dưới; kết quả thuộc một biến không liên quan có thể bỏ qua:

```bash
grep -rnE "backDropBlurs|themePath|outDir|resolveSpacingProps|COLOR_STATES|splitLayout\(|themeAxisAttributes<|ResponsiveValueStrict|DefaultBreakpointKeys|SpacingKey\b|RecipeFn|extraSources" --include='*.ts' --include='*.tsx' --include='*.mts' --include='*.cts' --include='*.jsx' --include='*.vue' --include='*.js' --include='*.mjs' --include='*.cjs' --include='*.json' --exclude-dir=node_modules .
```

Ghim phiên bản chính xác, đổi config, lời gọi plugin và các import trong cùng một commit, chạy `style-gen schema` để sinh lại `theme.schema.json` và `style-gen.config.schema.json` đã commit (cả `generate` lẫn `init` đều không ghi lại chúng, nên chúng giữ các key của 7.x), rồi chạy `style-gen doctor` và `style-gen generate --check` trước khi merge. `style-gen schema` ghi `theme.schema.json` cạnh theme (`--out` phải nằm trong gốc dự án) và `style-gen.config.schema.json` ở thư mục gốc (`--config-out`); một config đã có không được thêm key `$schema`, nên hãy tự thêm `"$schema": "./style-gen.config.schema.json"` làm key đầu tiên của nó (chỉ `init` cho config mới mới ghi key này).

## B1. Plugin chỉ nhận `root`

`styleGenVite` và `styleGenNext` không còn nhận `themePath`, `outDir` hay `options`. Mọi tùy chọn của generator nằm trong `style-gen.config.json` (hoặc `package.json["style-gen"]`).
Chuyển `themePath` sang `theme`, `outDir` sang thư mục của `output`, và `options` sang các key tương ứng trong file config. `root` là thư mục chứa `style-gen.config.json`; mọi đường dẫn trong config được phân giải từ đó.
Truyền bất kỳ key nào khác sẽ ném lỗi trỏ tới mục này.

Trước:

```ts
// vite.config.ts
import { options } from "./src/options";

export default defineConfig({
  plugins: [
    styleGenVite({
      themePath: "src/theme/theme.json",
      outDir: "src/theme",
      options,
    }),
  ],
});
```

Sau:

```json
{
  "theme": "src/theme/theme.json",
  "output": "src/theme/theme.css",
  "coverage": { "colors": { "opacities": [10, 20, 50, 80] } }
}
```

```ts
// vite.config.ts
export default defineConfig({
  plugins: [styleGenVite()],
});
```

Next.js: `styleGenNext({ themePath, outDir, options })(nextConfig)` trở thành `styleGenNext()(nextConfig)`.
Nuxt chạy config từ một thư mục khác, nên hãy đưa root vào: `styleGenVite({ root: fileURLToPath(new URL(".", import.meta.url)) })`.

## B2. `theme.tokens.ts` được sinh ở mỗi lần emit

Các plugin và `style-gen generate` ghi `theme.tokens.ts` cạnh `theme.css` (key config `tokensOutput`; mặc định: thư mục của `output`).
Code của app import `tokens` từ file đó thay vì gọi `createDesignTokens(theme, options)`, nên `options.ts` bị xóa. `createDesignTokens` vẫn còn cho một theme thứ hai tạo ở runtime.
Hãy commit file tokens, để `theme.css` trong git-ignore, và thêm `style-gen generate --check` vào CI: lệnh này không ghi gì và thoát với mã 1 khi file tokens thiếu hoặc khác với theme và config.
File export `tokens`, `Tokens`, `themeAxes` và `ThemeAxesState`.
Prettier là formatter duy nhất để yên cho file này: file có một dòng `// prettier-ignore` trước mỗi export và không có gì khác. Hãy loại `theme.tokens.ts` khỏi mọi công cụ khác có thể ghi lại file (Biome, dprint, oxfmt, ESLint với rule stylistic cùng `--fix`, một glob của lint-staged): việc ghi lại khiến `style-gen generate --check` báo file đã lỗi thời.

Trước:

```ts
// src/theme.ts
import { createDesignTokens } from "@duydpdev/style-generator/tokens";

import { options } from "./options";
import themeJson from "./theme/theme.json";

export const tokens = createDesignTokens(themeJson, options).DesignTokens.Web;
```

Sau:

```ts
// src/theme.ts
import themeJson from "./theme/theme.json";

export { tokens, type Tokens } from "./theme/theme.tokens";
export const theme = themeJson;
```

```bash
style-gen generate --check
```

## B3. Đường dẫn mặc định của `style-gen tokens`

`style-gen tokens` giờ ghi cạnh `output` (trước đây ghi cạnh file theme). `--out` không đổi.

Trước:

```bash
style-gen tokens
# wrote src/theme/theme.tokens.ts, next to theme.json
```

Sau:

```bash
style-gen tokens
# writes next to the file named by "output" in style-gen.config.json
```

## B4. `themeAxisAttributes` không còn là generic

`themeAxisAttributes<typeof theme>(state)` trở thành `themeAxisAttributes(state)`. Gõ kiểu cho state bằng `ThemeAxesState` từ file đã sinh.
Một state được khai báo bằng `interface` không còn biên dịch được (TS2345: một interface không có index signature ngầm định, thứ mà `Record<string, string | undefined>` yêu cầu). Hãy khai báo nó bằng một `type` alias, hoặc dùng `ThemeAxesState`.

Trước:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { theme } from "./theme";

const attributes = themeAxisAttributes<typeof theme>({ theme: "dark" });
```

Sau:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { ThemeAxesState } from "./theme/theme.tokens";

const state: ThemeAxesState = { theme: "dark" };
const attributes = themeAxisAttributes(state);
```

## B5. `backDropBlurs` giờ là `backdropBlurs`

Key của theme, `themeAxes.<axis>.<variant>.backdropBlurs`, `DesignTokens.Web.backdropBlurs`, `coverage.backdropBlurs`, `RecipeTokens.backdropBlurs` và input của `createCn` được đổi tên. Các class và biến `--sg-backdrop-blur-*` không đổi.
Tìm mọi chỗ dùng bằng `grep -rl backDropBlurs .`.
Một `theme.schema.json` đã commit vẫn liệt kê key cũ, nên hãy sinh lại nó bằng `style-gen schema`; schema của một dự án 4.x còn có thêm giới hạn của `typography.*.fontWeight` (1 đến 1000) và không còn liệt kê `letterSpacing` là bắt buộc. Nếu bạn dựng instance `tailwind-merge` bằng `createTailwindMergeExtension` (`./recipes`), input `TailwindMergeTokens` của nó cũng đọc `backdropBlurs`: truyền các token từ `theme.tokens.ts` thì việc đổi tên tự đi theo.

Trước:

```json
{ "colors": { "primary": "#0af" }, "backDropBlurs": { "md": "12px" } }
```

Sau:

```json
{ "colors": { "primary": "#0af" }, "backdropBlurs": { "md": "12px" } }
```

## B6. Mỗi symbol chỉ có một nơi export

Các symbol được nêu ở đây chỉ được export từ một subpath. `COLOR_STATES` lấy từ `@duydpdev/style-generator/cva` (đã gỡ khỏi `./tokens`). `DefaultBreakpointKeys`, `ResponsiveValueStrict` và `SpacingKey` lấy từ `@duydpdev/style-generator/types` (đã gỡ khỏi `.` và `./spacing`). Các kiểu của theme, option và token (`ThemeConfig`, `StyleGeneratorOptions`, `DesignTokensWeb`, `ColorVariant`, …) vẫn được export từ cả `.` lẫn `./types`.

Trước:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/tokens";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/spacing";
```

Sau:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/cva";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/types";
```

## B7. `resolveSpacingProps` bị gỡ

Dùng `splitSpacingProps` (`./recipes`) hoặc `splitSpacing` (`./ui`) cho props của component, hoặc gọi `resolveSpacing` cho từng thuộc tính.
Props spacing là camelCase: `gap-x` là prop `gapX`. Một key kebab-case như `"gap-x"` không phải prop spacing, nên `splitSpacing` để nó lại trong `rest` thay vì biến nó thành class.

Trước:

```ts
import { resolveSpacingProps } from "@duydpdev/style-generator/spacing";

const { classNames, style } = resolveSpacingProps({
  p: props.p,
  m: props.m,
});
```

Sau:

```ts
import { splitSpacing } from "@duydpdev/style-generator/ui";

const { className, style, rest } = splitSpacing(
  props,
  tokens.spacingProperties,
);
```

## B8. `splitLayout` nhận một object tùy chọn

Các đối số vị trí sau `props` gộp thành một object.

Trước:

```ts
const split = splitLayout(
  props,
  box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
);
```

Sau:

```ts
const split = splitLayout(props, {
  recipe: box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
});
```

## B9. `RecipeFn` có kiểu theo các bảng của nó

`recipeFromTables(tables)` trả về một hàm có kiểu tham số suy ra từ các bảng, nên tên variant gõ sai (`intnet: "primary"`) là lỗi biên dịch, và một giá trị mà bảng không khai báo cũng vậy. Mỗi variant chỉ nhận các key option của chính nó; key `"true"`/`"false"` nghĩa là boolean, và một key số (`10`) nhận cả số lẫn dạng chuỗi của nó. Các trường hợp sau giờ lỗi với TS2322:

- một prop bị nới rộng: `size: string`;
- một biểu thức điều kiện có thể là `false`: `cond && "sm"`;
- một prop `number` truyền vào variant có các key là literal số (`10 | 20`);
- một literal mà bảng không khai báo: `size: "xl"`;
- `true` hoặc một số trên variant mà các key là chuỗi thường.

Hãy thu hẹp giá trị (`cond ? "sm" : undefined`, một union type cho prop) hoặc khai báo option trong bảng. Chú thích `: RecipeFn` vẫn biên dịch được: nó chỉ khiến recipe đó bỏ qua việc kiểm tra (`RecipeFn` là kiểu lỏng `(props?: RecipeProps) => string`), nên tên và giá trị lạ lại được chấp nhận. Hãy bỏ chú thích để có kiểm tra; những tên mà nó giờ báo lỗi trước đây bị bỏ qua âm thầm.

Để tìm các chú thích và import của chúng, chạy `grep -rnE ':\s*RecipeFn\b|\bRecipeFn\b.*from' --include='*.ts' --include='*.tsx' --include='*.vue' --exclude-dir=node_modules .`: xóa từng `: RecipeFn` và import `type RecipeFn` còn thừa.

Trước:

```ts
export const buttonRecipe: RecipeFn = recipeFromTables(buttonTables);
```

Sau:

```ts
export const buttonRecipe = recipeFromTables(buttonTables);
```

## B10. Các helper migration bị gỡ

`style-gen doctor` không còn quét file nguồn của bạn để tìm các biến `--sg-<color>` trước 5.0. `style-gen init` không còn bỏ hay báo các key config đã gỡ (`plugin`, `extraSources`, `axes`) của một config có sẵn: một config còn một key như vậy là không hợp lệ, và `init` để nguyên từng byte, kèm cảnh báo (nó giữ `theme` và `output` mà config khai báo); khi bạn chọn một theme khác bằng `--theme` hoặc trình hướng dẫn, `init` chỉ gộp `theme` đó vào và cảnh báo `style-gen.config.json is invalid and init only merged the theme into it; generate rejects it:`. Mọi lệnh đọc config (`generate`, `doctor`, các plugin) từ chối key đó với `<key> → Unrecognized key`, nên hãy tự xoá nó; hãy khai báo các class tạo lúc runtime bằng `@source inline(...)` của riêng bạn cạnh dòng import file được sinh. Một key `themes` trong file theme không còn có thông báo đổi tên riêng: nó cho ra cùng lỗi `Unrecognized key` như mọi key không biết khác.
Nếu bạn đang ở 6.x hoặc cũ hơn, hãy nâng lên 7.x trước và làm theo các hướng dẫn đó.

Trước:

```json
{
  "theme": "src/theme/theme.json",
  "extraSources": ["hover:bg-{primary,secondary}"]
}
```

Sau:

```json
{ "theme": "src/theme/theme.json" }
```

## Mới trong 8.0 (không cần đổi gì)

`style-gen generate --check`; key config `tokensOutput`; `style-gen schema` cũng ghi `style-gen.config.schema.json` (`--config-out`), file mà editor dùng cho key `$schema` của file config; `style-gen init --yes` trả lời mọi câu hỏi bằng giá trị mặc định và không bao giờ ghi đè một file đã có.

`init --yes` giữ nguyên config có sẵn: theme và output mà nó nêu vẫn như đã cấu hình, và chỉ các file còn thiếu mới được ghi. Nó thoát với mã 1 khi config đó không hợp lệ hoặc khi `--theme` nêu một theme khác. Một config 7.x còn key đã gỡ (`extraSources`, `axes`, `plugin`) chính là một config như vậy, nên hãy tự xoá key đó (B10) trước khi chạy, hoặc chỉ làm mới các quy tắc cho agent bằng `style-gen init --rules-only` (các dòng CSS nó in lấy từ config trong thư mục hiện tại: nếu ở đó không có config, chúng là giá trị mặc định cho một config đầu tiên, nên hãy bỏ qua khi config của bạn nằm trong một thư mục con). Không có `--yes` và không có terminal, một lần `init` trên config khai báo một theme đã tồn tại thoát với mã 1 (`Files already exist`), hợp lệ hay không. 8.0.2 cũng siết quy tắc file-khác-nhau của `generate`, `doctor`, `schema` và các plugin: một thiết lập có `output` tới theme, file tokens, `style-gen.config.json` hoặc `package.json` qua chữ hoa/thường khác hay symlink từng thoát với mã 0 và nay thoát với mã 1, và các plugin ném lỗi khi khởi động ([must be different files](../troubleshooting.md#must-be-different-files)).

```bash
style-gen schema --config-out style-gen.config.schema.json
style-gen init --yes
```

## Rollback

Ghim 7.x (`yarn add @duydpdev/style-generator@7.2.1`), rồi hoàn tác config, lời gọi plugin và các import.

```bash
yarn add @duydpdev/style-generator@7.2.1
```
