# Migrating from 6.x to 7.0

7.0.0 removes three generator options: `extraSources`, `axes.attribute` and `axes.scope` (so the whole `axes` option is gone). The generated CSS and the `--sg-*` variables are unchanged for every theme that did not use them: regenerating `theme.css` after the upgrade produces the same file.

For earlier upgrades see [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) and [`3.x-to-4.0.md`](./3.x-to-4.0.md). The full rules live in [`README.md`](../../README.md).

## Before you upgrade

**1. Find every use of the removed options.** Run this from your repository root; a hit in a `generate()` call, in `style-gen.config.json` or in `package.json["style-gen"]` must be migrated (the sections below say how). Unrelated hits (a variable called `axes` in a chart, for example) can be ignored:

```bash
git grep -n -E 'extraSources|axes'
```

**2. Check how you read the theme attributes.** A call such as `themeAxisAttributes(state, attribute)` with a second argument fails type-checking in 7.0 (see [`axes.attribute` removed](#axesattribute-removed)).

**3. Pin the version exactly** (`7.0.0`), change the config and the pin in one commit, and run `style-gen doctor` before merging.

## Breaking changes

### `extraSources` removed

Classes built at runtime (a template literal such as `` `bg-${variant}` ``) cannot be scanned by Tailwind. Until 6.x the generator wrote them into the generated CSS as extra `@source inline("<entry>")` lines. In 7.0 the app declares them itself, in its own CSS next to the generated import, with the plain Tailwind directive (or lets them appear literally in source):

```ts
// 6.x: generate(theme, { extraSources: ["hover:bg-{primary,secondary}"] })
```

```css
/* 7.0: app.css */
@import "tailwindcss";
@import "./theme.css";
@source inline("hover:bg-{primary,secondary}");
```

The same applies to the `extraSources` key of `style-gen.config.json` and to the `{ allowUnregisteredPrefix: true }` opt-out of `createVariantMapper`: the classes it maps are now declared with `@source inline(...)` in the app's CSS.

### `axes.attribute` removed

The selector of a theme axis is always `html[data-<axis-kebab>="<variant-kebab>"]`: axis `theme`, variant `dark` → `html[data-theme="dark"]`; axis `colorMode`, variant `highContrast` → `html[data-color-mode="high-contrast"]`. `themeAxisAttributes(state)` takes one argument and always emits `data-<axis-kebab>`:

```ts
// 6.x
generate(theme, { axes: { attribute: { theme: "data-mode" } } });
themeAxisAttributes<typeof theme>({ theme: "dark" }, { theme: "data-mode" });

// 7.0
generate(theme);
themeAxisAttributes<typeof theme>({ theme: "dark" }); // { "data-theme": "dark" }
```

If you need a different attribute name, rename the axis in `themeAxes` (axis `mode` gives `data-mode`) or write the override CSS by hand, as described in the next section.

### `axes.scope` removed

The selector is always pinned to `html`, which is what `scope: "root"` did (the default). A `$`-alias `var()` is evaluated where the custom property is declared (`:root`), so an override on a child element never reached the alias value; this is why the library no longer offers `scope: "element"`.

For a scoped theme on a non-root element, or a custom attribute name, write the override CSS by hand in the app's CSS and re-declare every alias holder it affects:

```css
/* 7.0: app.css */
[data-mode="dark"] {
  --sg-color-primary: #93c5fd;
  --sg-color-text: #f8fafc;
}
```

### Removed keys are rejected

A removed key fails like any other unknown key; nothing is ignored silently:

- `generate()` throws a `ZodError` with an `unrecognized_keys` issue at the key's path (`extraSources`, `axes`).
- `style-gen generate` exits 1 with `Invalid options:` (flags) or, for the config file, `Invalid config (style-gen.config.json):` followed by `extraSources → Unrecognized key: "extraSources"` or `axes → Unrecognized key: "axes"`. `--watch` reports the same and keeps the last valid config.
- `style-gen doctor` exits 1 and prints `Config (style-gen.config.json) ❌ Invalid` with the same `path → message` line.

## Migration checklist

- [ ] `git grep -n -E 'extraSources|axes'` shows no `generate()` option, config key or `package.json["style-gen"]` entry left.
- [ ] Every former `extraSources` entry is an `@source inline("...")` line in the app's CSS next to the generated import.
- [ ] Every `themeAxisAttributes(state, attribute)` call passes only `state`; the DOM attribute is `data-<axis-kebab>`.
- [ ] Every former `axes.scope: "element"` or custom attribute is replaced by hand-written override CSS.
- [ ] `style-gen doctor` reports no invalid config and `style-gen generate` writes the same CSS as before.

## Rollback

Pin `6.x` (`yarn add @duydpdev/style-generator@6.0.0`). The changes are config, CSS and call-site edits only, so reverting them restores the 6.x behavior.
