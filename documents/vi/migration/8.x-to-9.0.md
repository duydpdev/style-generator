# Nâng cấp từ 8.x lên 9.0

9.0.0 hoàn tất thay đổi cách đặt tên màu mà 8.3 đã đánh dấu deprecated: `contrastText` chỉ đọc `<intent>Foreground`, `COLOR_STATES` trở thành một bảng và ánh xạ thêm sibling `Selected` sang `aria-selected:`, và script wrapper canvas chỉ có trong repository bị gỡ.
CSS sinh ra và các biến `--sg-*` không đổi với một theme đã dùng tên v2; một theme có màu `<intent>Selected` có thêm một dòng `@source inline("aria-selected:…")`.

Với các lần nâng cấp trước, xem [`7.x-to-8.0.md`](./7.x-to-8.0.md), [`6.x-to-7.0.md`](./6.x-to-7.0.md), [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) và [`3.x-to-4.0.md`](./3.x-to-4.0.md). Các quy tắc đầy đủ nằm trong [`README.md`](../../README.md).

## Trước khi nâng cấp

Trước hết nâng cấp lên bản 8.x mới nhất và chạy `style-gen doctor`: lệnh này cảnh báo mọi key `on<Intent>` có `<intent>` là một màu và nêu tên key cần đổi sang. Doctor của 8.x bỏ qua một key trạng thái như `onPrimaryHover` khi theme không có màu `primaryHover`; lệnh grep dưới đây tìm ra nó, và doctor của 9.0.1 cảnh báo nó. Sau đó chạy lệnh này từ thư mục gốc repo; mỗi kết quả tìm thấy được xử lý bởi một mục bên dưới:

```bash
grep -rnE "\bon[A-Z][a-zA-Z0-9]*\b|states: *\[|COLOR_STATES|check-design-canvas" --include='*.json' --include='*.ts' --include='*.tsx' --include='*.mts' --include='*.cts' --include='*.vue' --include='*.js' --include='*.mjs' --include='*.yml' --exclude-dir=node_modules .
```

Kết quả như `onClick` hay `onboarding` không phải key màu và có thể bỏ qua.

## B1. `contrastText` chỉ đọc `<intent>Foreground`

`contrastText(colors, intent, fallback)` từng trả `text-on-<intent>` khi theme khai báo `on<Intent>` mà không có `<intent>Foreground`. Giờ nó trả `text-<intent>-foreground` hoặc `text-<fallback>`; key `on<Intent>` không được đọc, nên một button dựa vào nó sẽ hiển thị màu chữ fallback.
Đổi tên từng key trong `theme.json`, kể cả các override `themeAxes`, và mọi class nhắc tới nó:

| Key 8.x          | Key 9.0                  | Class                                                                 |
| ---------------- | ------------------------ | --------------------------------------------------------------------- |
| `onPrimary`      | `primaryForeground`      | `text-on-primary` → `text-primary-foreground`                         |
| `onDanger`       | `dangerForeground`       | `text-on-danger` → `text-danger-foreground`                           |
| `onPrimaryHover` | `primaryForegroundHover` | `hover:text-on-primary-hover` → `hover:text-primary-foreground-hover` |
| `on<Intent>`     | `<intent>Foreground`     | `text-on-<intent>` → `text-<intent>-foreground`                       |

Trạng thái chuyển ra sau `Foreground`, vì `createVariantMapper` tìm sibling trạng thái theo dạng `<token>` + trạng thái. Khi theme đã có key 9.0, hãy tự gộp hai màu thay vì đổi tên: `style-gen doctor` in `<target> exists: merge <key> into it and remove <key>` cho trường hợp đó.

Trước:

```json
{ "colors": { "primary": "#2563EB", "onPrimary": "$white" } }
```

Sau:

```json
{ "colors": { "primary": "#2563EB", "primaryForeground": "$white" } }
```

Sinh lại `theme.css` và `theme.tokens.ts` (`style-gen generate`, hoặc khởi động dev server), rồi chạy `style-gen doctor`: lệnh không in dòng `on<Intent>` nào khi mọi key đã được đổi tên.

## B2. `COLOR_STATES` là một bảng; `states` nhận `ColorState[]`

`COLOR_STATES` từng là `["hover", "active"]`. Giờ nó là một bảng các dòng `{ suffix, variant }`, export từ `./cva` cùng kiểu `ColorState`:

```ts
[
  { suffix: "Hover", variant: "hover" },
  { suffix: "Active", variant: "active" },
  { suffix: "Selected", variant: "aria-selected" },
];
```

`suffix` được nối vào một key màu để tìm sibling của nó (`primary` + `Selected` → `primarySelected`) và `variant` là variant Tailwind đứng trước class của sibling (`aria-selected:bg-primary-selected`, áp dụng khi phần tử có `aria-selected="true"`). Registry sinh dòng `@source inline` tương ứng, nên class được build.

Mã truyền `{ states: COLOR_STATES }` không cần sửa. Mọi cách dùng `COLOR_STATES` khác giờ đọc các dòng của bảng, không phải chuỗi: một template literal như `` `${state}:…` `` vẫn biên dịch nhưng tạo ra `[object Object]:…`, `(typeof COLOR_STATES)[number]` là một dòng (`{ suffix: "Hover"; variant: "hover" } | …`, gán được cho `ColorState`), không phải `"hover" | "active"`, và `(typeof COLOR_STATES)[number]["variant"]` là `"hover" | "active" | "aria-selected"`, nên một `switch` trên union cũ sẽ gặp giá trị thứ ba; dùng `state.variant` cho variant Tailwind và `state.suffix` cho hậu tố của key. Một danh sách tên trạng thái tự gõ là lỗi kiểu; hãy viết các dòng của bảng:

Trước:

```ts
createVariantMapper("bg", tokens.colors, { states: ["hover"] });
```

Sau:

```ts
import {
  createVariantMapper,
  type ColorState,
} from "@duydpdev/style-generator/cva";

const states = [
  { suffix: "Hover", variant: "hover" },
] as const satisfies readonly ColorState[];
createVariantMapper("bg", tokens.colors, { states });
```

Một tên trạng thái mà 8.x tự chuyển sang kebab-case (`"focusVisible"`) trở thành một dòng có variant Tailwind viết rõ: `{ suffix: "FocusVisible", variant: "focus-visible" }`. Lệnh grep ở trên chỉ tìm danh sách viết trực tiếp; hãy kiểm tra cả danh sách `states` lưu trong một biến. Giữ danh sách ở dạng literal (`as const`) để mapper trả về kiểu class literal. Một trạng thái không có trong `COLOR_STATES` không có dòng `@source inline`, nên hãy tự khai báo các class của nó bằng `@source inline(...)` cạnh dòng import file sinh ra.

Một key màu vốn đã kết thúc bằng `Selected` (`rowSelected` cạnh `row`) giờ thêm class `aria-selected:` vào key gốc. Hãy đổi tên nó nếu đó không phải điều bạn muốn.

## B3. `scripts/check-design-canvas.mjs` bị gỡ

Wrapper chỉ có trong repository, vốn chuyển tiếp sang bộ kiểm tra canvas, đã bị gỡ. Hãy chạy lệnh CLI; manifest mặc định nằm ở `node_modules/@duydpdev/style-generator/dist/canvas/design-canvas-standard.json`.

Trước:

```bash
node scripts/check-design-canvas.mjs --canvas design/canvas --theme styles/theme.json
```

Sau:

```bash
style-gen canvas check --canvas design/canvas --theme styles/theme.json
```

Xem [`style-gen canvas check`](../reference/cli.md) để biết các flag.

## Rollback

Ghim bản 8.x cuối cùng, rồi hoàn tác các lần đổi tên trong theme và các thay đổi `states`.

```bash
yarn add @duydpdev/style-generator@8.3.0
```
