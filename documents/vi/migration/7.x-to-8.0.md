# Nâng cấp từ 7.x lên 8.0

8.0.0 chuyển mọi tùy chọn của generator vào `style-gen.config.json`, để các plugin và `style-gen generate` cùng ghi một file `theme.tokens.ts` có kiểu, đổi tên `backDropBlurs` thành `backdropBlurs`, và gỡ mã migration của những phiên bản chưa từng lên npm.
CSS sinh ra, các biến `--sg-*` và kết quả `@source inline` không đổi: sinh lại `theme.css` sau khi nâng cấp cho ra đúng file cũ.

Với các lần nâng cấp trước, xem [`6.x-to-7.0.md`](./6.x-to-7.0.md), [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) và [`3.x-to-4.0.md`](./3.x-to-4.0.md). Các quy tắc đầy đủ nằm trong [`README.md`](../../README.md).

## Trước khi nâng cấp

Chạy lệnh này từ thư mục gốc repo. Mỗi kết quả tìm thấy được xử lý bởi một mục bên dưới; kết quả thuộc một biến không liên quan có thể bỏ qua:

```bash
grep -rnE "backDropBlurs|themePath|outDir|resolveSpacingProps|COLOR_STATES|splitLayout\(" --include=*.ts --include=*.tsx --include=*.vue --include=*.json .
```

Ghim phiên bản chính xác, đổi config, lời gọi plugin và các import trong cùng một commit, rồi chạy `style-gen doctor` và `style-gen generate --check` trước khi merge.

## B1. Plugin chỉ nhận `root`

`styleGenVite` và `styleGenNext` không còn nhận `themePath`, `outDir` hay `options`. Mọi tùy chọn của generator nằm trong `style-gen.config.json` (hoặc `package.json["style-gen"]`).
Chuyển `themePath` sang `theme`, `outDir` sang thư mục của `output`, và `options` sang các key tương ứng trong file config. `root` là thư mục chứa `style-gen.config.json`; mọi đường dẫn trong config được phân giải từ đó.
Truyền bất kỳ key nào khác sẽ ném lỗi trỏ tới mục này.

Trước:

```ts
// vite.config.ts
import { options } from "./src/options";

export default defineConfig({
  plugins: [
    styleGenVite({
      themePath: "src/theme/theme.json",
      outDir: "src/theme",
      options,
    }),
  ],
});
```

Sau:

```json
{
  "theme": "src/theme/theme.json",
  "output": "src/theme/theme.css",
  "coverage": { "colors": { "opacities": [10, 20, 50, 80] } }
}
```

```ts
// vite.config.ts
export default defineConfig({
  plugins: [styleGenVite()],
});
```

Next.js: `styleGenNext({ themePath, outDir, options })(nextConfig)` trở thành `styleGenNext()(nextConfig)`.
Nuxt chạy config từ một thư mục khác, nên hãy đưa root vào: `styleGenVite({ root: fileURLToPath(new URL(".", import.meta.url)) })`.

## B2. `theme.tokens.ts` được sinh ở mỗi lần emit

Các plugin và `style-gen generate` ghi `theme.tokens.ts` cạnh `theme.css` (key config `tokensOutput`; mặc định: thư mục của `output`).
Code của app import `tokens` từ file đó thay vì gọi `createDesignTokens(theme, options)`, nên `options.ts` bị xóa. `createDesignTokens` vẫn còn cho một theme thứ hai tạo ở runtime.
Hãy commit file tokens, để `theme.css` trong git-ignore, và thêm `style-gen generate --check` vào CI: lệnh này không ghi gì và thoát với mã 1 khi file tokens thiếu hoặc khác với theme và config.
File export `tokens`, `Tokens`, `themeAxes` và `ThemeAxesState`.

Trước:

```ts
// src/theme.ts
import { createDesignTokens } from "@duydpdev/style-generator/tokens";

import { options } from "./options";
import themeJson from "./theme/theme.json";

export const tokens = createDesignTokens(themeJson, options).DesignTokens.Web;
```

Sau:

```ts
// src/theme.ts
import themeJson from "./theme/theme.json";

export { tokens, type Tokens } from "./theme/theme.tokens";
export const theme = themeJson;
```

```bash
style-gen generate --check
```

## B3. Đường dẫn mặc định của `style-gen tokens`

`style-gen tokens` giờ ghi cạnh `output` (trước đây ghi cạnh file theme). `--out` không đổi.

Trước:

```bash
style-gen tokens
# wrote src/theme/theme.tokens.ts, next to theme.json
```

Sau:

```bash
style-gen tokens
# writes next to the file named by "output" in style-gen.config.json
```

## B4. `themeAxisAttributes` không còn là generic

`themeAxisAttributes<typeof theme>(state)` trở thành `themeAxisAttributes(state)`. Gõ kiểu cho state bằng `ThemeAxesState` từ file đã sinh.

Trước:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { theme } from "./theme";

const attributes = themeAxisAttributes<typeof theme>({ theme: "dark" });
```

Sau:

```ts
import { themeAxisAttributes } from "@duydpdev/style-generator/recipes";

import type { ThemeAxesState } from "./theme/theme.tokens";

const state: ThemeAxesState = { theme: "dark" };
const attributes = themeAxisAttributes(state);
```

## B5. `backDropBlurs` giờ là `backdropBlurs`

Key của theme, `themeAxes.<axis>.<variant>.backdropBlurs`, `DesignTokens.Web.backdropBlurs`, `coverage.backdropBlurs`, `RecipeTokens.backdropBlurs` và input của `createCn` được đổi tên. Các class và biến `--sg-backdrop-blur-*` không đổi.
Tìm mọi chỗ dùng bằng `grep -rl backDropBlurs .`.

Trước:

```json
{ "colors": { "primary": "#0af" }, "backDropBlurs": { "md": "12px" } }
```

Sau:

```json
{ "colors": { "primary": "#0af" }, "backdropBlurs": { "md": "12px" } }
```

## B6. Mỗi symbol chỉ có một nơi export

Mỗi symbol chỉ được export từ một subpath. `COLOR_STATES` lấy từ `@duydpdev/style-generator/cva` (đã gỡ khỏi `./tokens`). `DefaultBreakpointKeys`, `ResponsiveValueStrict` và `SpacingKey` lấy từ `@duydpdev/style-generator/types` (đã gỡ khỏi `.` và `./spacing`).

Trước:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/tokens";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/spacing";
```

Sau:

```ts
import { COLOR_STATES } from "@duydpdev/style-generator/cva";
import type { ResponsiveValueStrict } from "@duydpdev/style-generator/types";
```

## B7. `resolveSpacingProps` bị gỡ

Dùng `splitSpacingProps` (`./recipes`) hoặc `splitSpacing` (`./ui`) cho props của component, hoặc gọi `resolveSpacing` cho từng thuộc tính.

Trước:

```ts
import { resolveSpacingProps } from "@duydpdev/style-generator/spacing";

const { className, style } = resolveSpacingProps(
  props,
  tokens.spacingProperties,
);
```

Sau:

```ts
import { splitSpacing } from "@duydpdev/style-generator/ui";

const { className, style, rest } = splitSpacing(
  props,
  tokens.spacingProperties,
);
```

## B8. `splitLayout` nhận một object tùy chọn

Các đối số vị trí sau `props` gộp thành một object.

Trước:

```ts
const split = splitLayout(
  props,
  box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
);
```

Sau:

```ts
const split = splitLayout(props, {
  recipe: box,
  spacingKeys,
  variantKeys,
  sizeKeys,
  extra,
});
```

## B9. `RecipeFn` có kiểu theo các bảng của nó

`recipeFromTables(tables)` trả về một hàm có kiểu tham số suy ra từ các bảng, nên một variant gõ sai là lỗi biên dịch. Hãy bỏ chú thích `RecipeFn`, hoặc truyền kiểu của bảng, ở chỗ bạn đã viết tay.

Trước:

```ts
export const buttonRecipe: RecipeFn = recipeFromTables(buttonTables);
```

Sau:

```ts
export const buttonRecipe = recipeFromTables(buttonTables);
```

## B10. Các helper migration bị gỡ

`style-gen doctor` không còn quét các biến `--sg-<color>` trước 5.0. `style-gen init` không còn bỏ các key config đã gỡ (`plugin`, `extraSources`, `axes`) khỏi một config có sẵn. Một key `themes` trong file theme giờ cho ra lỗi key không nhận diện thông thường.
Nếu bạn đang ở 4.x hoặc cũ hơn, hãy nâng lên 7.x trước và làm theo các hướng dẫn đó.

Trước:

```json
{
  "theme": "src/theme/theme.json",
  "extraSources": ["hover:bg-{primary,secondary}"]
}
```

Sau:

```json
{ "theme": "src/theme/theme.json" }
```

## Mới trong 8.0 (không cần đổi gì)

`style-gen generate --check`; key config `tokensOutput`; `style-gen schema` cũng ghi `style-gen.config.schema.json` (`--config-out`), file mà editor dùng cho key `$schema` của file config; `style-gen init --yes` trả lời mọi câu hỏi bằng giá trị mặc định và không bao giờ ghi đè một file đã có.

```bash
style-gen schema --config-out style-gen.config.schema.json
style-gen init --yes
```

## Rollback

Ghim 7.x (`yarn add @duydpdev/style-generator@7.2.1`), rồi hoàn tác config, lời gọi plugin và các import.

```bash
yarn add @duydpdev/style-generator@7.2.1
```
