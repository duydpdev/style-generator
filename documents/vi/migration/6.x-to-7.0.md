# Nâng cấp từ 6.x lên 7.0

7.0.0 gỡ ba option của generator: `extraSources`, `axes.attribute` và `axes.scope` (nên toàn bộ option `axes` không còn).
CSS được sinh ra và các biến `--sg-*` không đổi với mọi theme không dùng chúng: sinh lại `theme.css` sau khi nâng cấp cho ra đúng file cũ.

Các lần nâng cấp trước: xem [`5.x-to-6.0.md`](./5.x-to-6.0.md), [`4.x-to-5.0.md`](./4.x-to-5.0.md) và [`3.x-to-4.0.md`](./3.x-to-4.0.md). Toàn bộ quy tắc nằm trong [`README.md`](../README.md).

## Trước khi nâng cấp

**1. Tìm mọi chỗ dùng option đã bị gỡ.**
Chạy lệnh này từ thư mục gốc repository; mỗi kết quả nằm trong một lời gọi `generate()`, trong `style-gen.config.json` hoặc trong `package.json["style-gen"]` đều phải được chuyển đổi
(các mục bên dưới cho biết cách làm).
Kết quả không liên quan (ví dụ một biến tên `axes` trong biểu đồ) có thể bỏ qua:

```bash
git grep -n -E 'extraSources|axes'
```

**2. Kiểm tra cách bạn đọc attribute của theme.**
Một lời gọi như `themeAxisAttributes(state, { attribute })` có tham số thứ hai sẽ lỗi type-check ở 7.0 (xem [`axes.attribute` removed](#axesattribute-removed)).

**3. Ghim đúng phiên bản** (`7.0.0`), đổi config và phiên bản ghim trong cùng một commit, và chạy `style-gen doctor` trước khi merge.

## Thay đổi phá vỡ tương thích

### `extraSources` removed

Các class được ghép lúc chạy (một template literal như `` `bg-${variant}` ``) không thể được Tailwind quét.
Đến 6.x, generator ghi chúng vào CSS được sinh ra dưới dạng các dòng `@source inline("<entry>")` bổ sung.
Ở 7.0, chính app khai báo chúng trong CSS của mình, ngay cạnh dòng import file được sinh ra, bằng directive Tailwind thuần (hoặc để chúng xuất hiện nguyên văn trong mã nguồn):

```ts
// 6.x: generate(theme, { extraSources: ["hover:bg-{primary,secondary}"] })
```

```css
/* 7.0: app.css */
@import "tailwindcss";
@import "./theme.css";
@source inline("hover:bg-{primary,secondary}");
```

Điều tương tự áp dụng cho key `extraSources` của `style-gen.config.json` và cho tùy chọn thoát `{ allowUnregisteredPrefix: true }` của `createVariantMapper`:
các class nó ánh xạ giờ được khai báo bằng `@source inline(...)` trong CSS của app.

### `axes.attribute` removed

Selector của một theme axis luôn là `html[data-<axis-kebab>="<variant-kebab>"]`:
axis `theme`, variant `dark` → `html[data-theme="dark"]`; axis `colorMode`, variant `highContrast` → `html[data-color-mode="high-contrast"]`.
`themeAxisAttributes(state)` nhận một tham số và luôn sinh `data-<axis-kebab>`:

```ts
// 6.x
generate(theme, { axes: { attribute: { theme: "data-mode" } } });
themeAxisAttributes<typeof theme>(
  { theme: "dark" },
  { attribute: { theme: "data-mode" } },
);

// 7.0
generate(theme);
themeAxisAttributes<typeof theme>({ theme: "dark" }); // { "data-theme": "dark" }
```

Nếu cần tên attribute khác, hãy đổi tên axis trong `themeAxes` (axis `mode` cho ra `data-mode`) hoặc tự viết CSS override như mô tả ở mục kế tiếp.

### `axes.scope` removed

Selector luôn được ghim vào `html`, đúng như `scope: "root"` (mặc định) từng làm.
Một `var()` alias kiểu `$` được tính tại nơi custom property được khai báo (`:root`), nên một override trên element con không bao giờ tới được giá trị alias;
đó là lý do thư viện không còn cung cấp `scope: "element"`.

Với một theme có phạm vi trên element không phải root, hoặc một tên attribute tùy ý, hãy tự viết CSS override trong CSS của app và khai báo lại mọi alias holder mà nó ảnh hưởng:

```css
/* 7.0: app.css */
[data-mode="dark"] {
  --sg-color-primary: #93c5fd;
  --sg-color-text: #f8fafc;
}
```

### Removed keys are rejected

Một key đã bị gỡ lỗi như mọi key lạ khác; không có gì bị bỏ qua một cách âm thầm:

- `generate()` ném `ZodError` với một issue `unrecognized_keys` tại path của key (`extraSources`, `axes`).
- `style-gen generate` thoát với mã 1 khi một key đã bị gỡ nằm trong `style-gen.config.json` (hoặc `package.json["style-gen"]`) và in `Invalid config (style-gen.config.json):`
  theo sau là `extraSources → Unrecognized key: "extraSources"` hoặc `axes → Unrecognized key: "axes"`. `--watch` báo lỗi tương tự và giữ config hợp lệ gần nhất.
- `style-gen doctor` thoát với mã 1 và in `Config (style-gen.config.json) ❌ Invalid` cùng dòng `path → message` đó.
- Các tùy chọn truyền trực tiếp vào `styleGenVite({ … })` hoặc `styleGenNext({ … })` bị từ chối với `[style-gen-vite] Invalid options:` / `[style-gen-next] Invalid options:`
  theo sau là issue chỉ ra key đã bị gỡ; một key đã bị gỡ trong file config mà các plugin này đọc sẽ báo `Invalid config (style-gen.config.json):` như trên.

Cách sửa: xóa các key đã bị gỡ khỏi `style-gen.config.json`, hoặc chạy `style-gen init`, lệnh này bỏ `extraSources` và `axes` khi gộp phần còn lại của config.
Với mỗi key nó in ``Removed the `<key>` key from style-gen.config.json: 7.0 no longer accepts it.``, và một dòng `@source inline("<entry>");` cho mỗi entry `extraSources` cũ để dán vào CSS của app.

## Checklist nâng cấp

- [ ] `git grep -n -E 'extraSources|axes'` không còn option `generate()`, key config hay mục `package.json["style-gen"]` nào.
- [ ] Mỗi entry `extraSources` cũ là một dòng `@source inline("...")` trong CSS của app, cạnh dòng import file được sinh ra.
- [ ] Mỗi lời gọi `themeAxisAttributes(state, { attribute })` chỉ truyền `state`; attribute trong DOM là `data-<axis-kebab>`.
- [ ] Mỗi `axes.scope: "element"` hoặc attribute tùy ý cũ được thay bằng CSS override tự viết.
- [ ] `style-gen doctor` không báo config không hợp lệ và `style-gen generate` ghi ra đúng CSS như trước.
- [ ] Nếu bạn đã chạy `style-gen init`: `extraSources` và `axes` không còn trong `style-gen.config.json`, và các dòng `@source inline(...)` được in ra đã được dán vào CSS của app.

## Rollback

Ghim `6.x` (`yarn add @duydpdev/style-generator@6.0.0`). Các thay đổi chỉ là sửa config, CSS và chỗ gọi, nên hoàn tác chúng sẽ trả lại hành vi 6.x.
